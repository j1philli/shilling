# ICE & TURN Configuration

The server provides a dynamic ICE server configuration endpoint so clients do not need to hardcode STUN or TURN servers.

## Endpoint

```
GET /api/ice-servers?allowRelay=true
```

Returns a list of ICE server configurations with optional time-limited TURN credentials.

## Response Format

```json
{
  "iceServers": [
    {
      "urls": ["stun:stun.cloudflare.com:3478"]
    },
    {
      "urls": ["turn:turn.example.com:3478"],
      "username": "1709654400:shilling",
      "credential": "base64-hmac-sha1",
      "credentialType": "password"
    }
  ],
  "ttlSeconds": 86400
}
```

## STUN Only (Default)

When neither coturn nor Cloudflare TURN is configured, the endpoint returns only STUN servers. This is sufficient for many home and LAN setups.

## Hosted TURN Gating

TURN access requires an explicit `allowRelay=true` request from the device. Omitted or false requests receive STUN only. With consent, access is gated by auth mode:

- self-hosted mode: TURN is returned when TURN is configured
- hosted mode: TURN is returned only when the authenticated user's household has an active Silver or Gold entitlement

STUN is always returned.

## TURN Credentials

When `SHILLING_TURN_SECRET` is set, the server generates time-limited TURN credentials using coturn's `use-auth-secret` HMAC-SHA1 mechanism:

- **Username** — `{expiry-timestamp}:shilling`, where the expiry is the current time plus the configured TTL
- **Credential** — Base64-encoded HMAC-SHA1 of the username using the shared secret

These credentials expire after the TTL period, after which clients should request fresh ones.

## Cloudflare Realtime TURN

Create a TURN key in Cloudflare and set `SHILLING_CLOUDFLARE_TURN_KEY_ID` and
`SHILLING_CLOUDFLARE_TURN_API_TOKEN` on the server. The token stays server-side.
Do not set `SHILLING_TURN_URLS` or `SHILLING_TURN_SECRET` in this mode.
The server requests short-lived credentials from Cloudflare's
`generate-ice-servers` endpoint and returns Cloudflare's ICE server list with
`ttlSeconds`. `SHILLING_TURN_TTL` defaults to 86400 seconds and must be at most
172800 seconds (48 hours). If Cloudflare is unavailable, the endpoint returns
HTTP 502; clients use their STUN fallback.

Clients fetch ICE configuration before opening peer connections. Before the TTL
expires, they refresh credentials and recreate active peer connections so TURN
allocations can continue using valid credentials.

## Client Fallback

If the server is unreachable, clients fall back to Cloudflare's public STUN server (`stun:stun.cloudflare.com:3478`). TURN is not available in this case, and the app does not add a non-WebRTC fallback transport.
